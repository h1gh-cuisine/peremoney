# Модель данных

Источник истины — `server/prisma/schema.prisma`; изменения выполняются Prisma migrations.

## Основные сущности

- `Cabinet` — проект, provider ID, тип, цены/баланс, доступность разделов, расписание и интеграционные настройки.
- `User` — логин, bcrypt-хэш, роль, кабинет, активность и версия сессии.
- `Contact` — нормализованный ответ Leads Factory; уникальность `(cabinetId, providerAnswerId)`.
- `Lead` — квалифицированный контакт и локальные поля продажи; связь один-к-одному с Contact.
- `AnswerSyncRun` — аудит синхронизаций ответов.
- `SourceTag` — локальный срез тегов/источников и их метрики.
- `DomainSourceJob` — очередь отложенной обработки доменных источников.
- `ScheduledRun` — персистентная очередь планировщика.
- `PayerProfile` — JSON-реквизиты плательщика, один профиль на кабинет.
- `Payment` — счёт/оплата, банковские ID, idempotency key и статус создания.
- `BalanceEntry` — идемпотентная проводка денег и единиц.
- `TochkaWebhookEvent` — журнал принятых банковских событий.
- `ProviderProjectCreation` — идемпотентная state machine создания проекта.
- `FanoutSource`, `FanoutDestination`, `FanoutDelivery` — источник разветвления, назначения и доставки.

## Важные статусы

- Роли: `MASTER`, `FULL`, `LIMITED`.
- Проекты: `VDL`, `PACKAGE`, `NUMBERS`.
- Продажа: `UNPROCESSED`, `NEGOTIATION`, `NOT_TARGET`, `REFUSAL`, `BOUGHT`.
- Создание счёта: `PENDING`, `SUCCEEDED`, `UNCERTAIN`, `FAILED`.
- Задачи/доставки используют состояния ожидания, выполнения, успеха и ошибки.

## Инварианты

- Provider IDs индексируются и связывают локальные записи с внешними.
- Денежные суммы хранятся как `Decimal`, не floating point.
- Внешние события и проводки имеют уникальные ключи для защиты от повторов.
- Большинство дочерних данных удаляется каскадно с Cabinet; банковский audit event при удалении Payment сохраняется с nullable-ссылкой.
- Время хранится в UTC; отображение и расписание применяют нужную временную зону.
